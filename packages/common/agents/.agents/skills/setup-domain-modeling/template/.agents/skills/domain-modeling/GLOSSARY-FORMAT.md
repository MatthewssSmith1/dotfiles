# Glossary Format

## Rules

- Pick one canonical term per concept.
- Keep definitions to one or two sentences.
- Define what the concept is, not everything it does.
- Add `_Avoid_` only when rejected synonyms are useful.
- Include project-domain concepts rather than general programming vocabulary.
- Group terms under domain-area headings when a flat list no longer scans well.
- Use canonical capitalization for Domain Terms in documentation prose throughout the repo.
  - Source-code identifiers follow the language's normal casing conventions.

---

## Template

```md
**Term**:
One or two sentences defining what the Term is.
_Avoid_: rejected synonym, other rejected synonym
```
